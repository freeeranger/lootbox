## Design Specificity Verdict

**Strongly authored in semantics; moderately distinctive in interaction.** Lootbox's pack, dependency, map-role, model-format, source-safety, and Godot language is highly specific. The quiet toolbench visual system is coherent. The three-pane shell itself remains category-familiar; durable project provenance and visible library health would make the interaction model as specific as the vocabulary.

## Overall Impression

Lootbox no longer needs another integration layer. The Godot export/removal workflow is one of its strongest areas. The biggest opportunity is making trust persist across time: preserve selection, show whether the library is current, and make project/export relationships inspectable after the toast disappears.

## What's Working

1. **File safety is real product behavior.** Export review, dependency disclosure, modified-file preservation, safe conflict naming, and source-folder protection consistently support the local-first promise.
2. **The browser is operationally mature.** Virtualized grid/list views, keyboard navigation, bulk selection, filters, preview retry, drag-out, and resizable panes support real library work.
3. **The visual system is disciplined.** Neutral chrome, one warm signal, technical typography, quiet motion, and asset-led color form a coherent desktop tool.

## Cognitive Load

**Moderate: 3 of 8 checklist failures.** Single focus, grouping, hierarchy, one-at-a-time decisions, and progressive disclosure pass. Chunking, minimal choices, and working-memory support fail: Library exposes many sibling destinations, filters/classification selectors show long option sets, projects and collections are unbounded, and users must remember transient outcomes and hidden pack-menu recovery actions.

## Emotional Journey

First use and truthful waiting are strong. The post-import state is a valley: the user gets a brief completion notice but no durable scan summary or recommended next step. Export/removal is the high point because consequences and safeguards are explicit. The end state is underpowered because export provenance and modified/untracked outcomes disappear instead of becoming durable project state.

## Priority Issues

### [P1] Global shortcuts can destroy or divert in-progress work

**Why it matters:** `Escape` clears selection without checking whether a dialog or menu owns the key. Ctrl/Cmd shortcuts can also open search, filters, export, or collection creation while focus is inside another input or dialog. A large multi-selection can be lost accidentally.

**Fix:** scope selection shortcuts to the asset browser/document body, suppress them while overlays or editable controls own focus, and add regression tests that close dialogs without changing selection.

**Suggested command:** `$impeccable harden`

### [P1] Library health and freshness are hidden

**Why it matters:** users cannot see when packs were last scanned, whether disk contents changed, or whether the overall library has unavailable/missing items without visiting pack context menus. A local index is only useful while it is trusted.

**Fix:** add a Library Health smart view; show changed, missing, unavailable, and low-confidence counts; expose per-pack freshness; offer Rescan all, Review missing, and Fix location; end scans with durable indexed/skipped/missing summaries.

**Suggested command:** `$impeccable shape`

### [P1] Godot export lacks durable provenance and sync status

**Why it matters:** after completion, users cannot answer which projects contain an asset, when it was exported, whether the project copy is current, or which modified files Lootbox intentionally preserved. The strongest workflow becomes transient.

**Fix:** add per-project last export, manifest status, current/outdated/missing/modified counts, activity receipts, and review/re-export actions. Add an inspector section showing an asset's project memberships and status.

**Suggested command:** `$impeccable shape`

### [P1] Functional metadata is too small and too faint

**Why it matters:** sidebar descriptions and counts use 11px text at 70% muted opacity, yielding roughly 3.6:1 contrast on the sidebar background. Paths, counts, and status are functional information, not decoration.

**Fix:** remove reduced opacity from functional text, move important secondary content to 12px, retain 11px only for high-contrast technical values, and audit compact targets and live-region verbosity.

**Suggested command:** `$impeccable audit`

### [P2] Growing libraries lack repeatable discovery tools

**Why it matters:** search and filters are powerful but ephemeral. Flat, unbounded pack/project/collection lists and repeated query reconstruction create cognitive drag as the library grows.

**Fix:** add collapsible/sidebar-filtered groups, recent or pinned packs/projects, saved smart views, favorites, and tag autocomplete. Keep these opt-in so first use stays quiet.

**Suggested command:** `$impeccable shape`

## Persona Red Flags

**Alex — power user:** Escape can erase a large selection; repeated searches cannot be saved; maintenance is pack-by-pack; export history must be reconstructed manually.

**Jordan — first-timer:** import is clear, but the next useful action is not; Add to Godot only appears after selection; classification/grouping terminology lacks contextual explanation; missing recovery depends on discovering right-click behavior.

**Mira — indie Godot developer:** project membership and export freshness are invisible; preserved project edits are not durable state; license/source/attribution metadata is absent, forcing external notes before shipping purchased assets.

## Minor Observations

- Empty collections and empty Missing views fall through to generic “No matching assets.”
- Initial Godot export-preview failure closes review instead of preserving a retry path.
- Import cancellation remains disabled until the first progress callback provides an active job ID.
- The shortcut reference always describes Delete as “Remove from Lootbox,” even in a project view.
- Global `user-select: none` prevents ordinary metadata selection outside explicitly marked regions.
- Collection membership is an unfiltered, unbounded checkbox list.
- Import completion needs a richer durable receipt.
- License, source URL, author, and attribution/usage-note metadata are an important future product gap, but come after trust/freshness work.

## Questions to Consider

- Is the durable object after export a fleeting event, or a project sync relationship users can inspect months later?
- If Lootbox manages growing libraries, should users ever need to right-click a pack to discover missing files?
- Should Classification & grouping outrank Use in project and project status in the inspector?
- What minimum source/license/attribution record would let a developer confidently ship a downloaded asset?
