## Design Specificity Verdict

**Authored for Lootbox, not category-interchangeable—although its specificity comes more from disciplined structure than signature visual detail.**

The three-pane library/browser/inspector composition, asset previews, checkerboards, technical metadata, pack/project separation, texture classification, duplicates, and Godot workflow clearly belong to this product. The charcoal-and-gold system implements “The Quiet Toolbench” consistently.

Geist, Lucide, and Base UI remain generic ingredients. Future character should come from product truths—asset lineage, dependency readiness, export confidence, and source safety—not decorative theming.

**Deterministic scan:** one advisory finding across `src/`: `text-[0.8rem]` in `src/components/ui/button.tsx:26` falls outside the documented 11/12/14/16px type ramp. It is real design-system drift, not a false positive, but it is not a functional defect.

**Visual overlays:** unavailable. No browser automation or installed Playwright/Puppeteer fallback existed, so no reliable user-visible overlay was created. The evidence fallback was the complete source scan plus exact call-site inspection.

## Overall Impression

Lootbox already feels unusually mature for an asset-management tool: calm, dense, safe, and genuinely efficient. Its biggest weakness appears at its product payoff. Discovery is rich and reassuring, but “Add to Godot” becomes an opaque one-click handoff precisely when users most need destination, dependency, and conflict confidence.

Cognitive load is **moderate: 3/8 checklist failures**—chunking, minimal choices, and working-memory support. The complexity is mostly legitimate, but scope becomes hard to verify after filters and bulk selection are applied.

## What’s Working

1. **The design thesis is implemented.** Neutral chrome, one warm signal, compact typography, monospace facts, tonal layering, and restrained states all reinforce the Quiet Toolbench.

2. **Risky local-library actions earn trust.** Forget, purge, restore, backup, and cache flows frequently explain what remains untouched; small removals provide Undo.

3. **Expert efficiency is excellent.** Keyboard navigation, range selection, result-wide selection, bulk actions, grid/list modes, drag-out, and persistent panel widths form a credible power-user workflow.

## Priority Issues

### [P1] Godot export hides the consequences of the product’s key action

- **Why it matters:** Choosing a project immediately exports. Users cannot verify destination, dependencies, conflicts, unchanged files, or manifest behavior.
- **Fix:** Add a preflight with project name/path, `res://assets/lootbox`, selected assets, dependency summary, conflict policy, and manifest details. Follow it with progress and a result offering “Open project folder” and “Copy manifest path.”
- **Suggested command:** `$impeccable harden`

### [P1] Signature preview controls are not fully accessible

- **Why it matters:** Detail-header icon actions rely on tooltips rather than explicit button labels; waveform seeking is pointer-only; resize separators do not announce size; changing progress is not robustly announced.
- **Fix:** Label icon buttons, model waveform seeking as a keyboard slider, expose separator values and Home/End behavior, and announce progress through a polite live region.
- **Suggested command:** `$impeccable audit`

### [P2] Active filter scope disappears after application

- **Why it matters:** The toolbar reduces filters to a count and hover title; below 1150px even that count disappears. Users must remember why assets are missing.
- **Fix:** Put removable active-filter chips and Clear all in the context bar, retaining a compact count at narrow widths.
- **Suggested command:** `$impeccable clarify`

### [P2] Bulk editing hides which assets will change

- **Why it matters:** The toolbar shows only “N selected,” while inspector changes apply to the whole virtualized selection. Users can no longer audit names, types, packs, or mixed values.
- **Fix:** Add a compact selection summary, mixed-value status, and “Review selection.” Repeat affected counts beside mutations and confirm high-impact bulk classification/grouping above a threshold.
- **Suggested command:** `$impeccable layout`

### [P2] Errors expose technical detail without recovery actions

- **Why it matters:** Many failures surface raw exception strings and offer Copy/Dismiss, not Retry, Fix location, Maintenance, or diagnostics.
- **Fix:** Map known contexts to plain language and relevant next actions; keep raw detail behind “Copy technical details.”
- **Suggested command:** `$impeccable harden`

## Persona Red Flags

**Alex—power user:** Alex gets excellent navigation and batch tools, but cannot shortcut filters, view changes, Godot export, tags, or collections. Bulk scope is count-only, export is opaque, and view mode is not persisted.

**Sam—accessibility-dependent:** Sam encounters unlabeled detail-header icon buttons, pointer-only waveform seeking, value-less resizers, incomplete live announcements, and a persistent 11px metadata scale that may struggle at 200% zoom.

**Mira—indie technical artist:** Mira never sees the local-and-untouched promise during first import, loses filter and bulk scope visibility, and cannot inspect the dependency payload or manifest destination before the crucial Godot handoff.

## Minor Observations

- The empty inspector should teach “Select an asset, or use arrow keys to browse.”
- First-run copy should state that indexing stays local and leaves the folder unchanged.
- Maintenance success text needs an explicit status role.
- “See diagnostics” model failures should open Maintenance directly.
- `text-[0.8rem]` should become a documented type step or use the existing 12px control token.
- Collection, tag, and classification mutations need local busy states to prevent repeat activation.

## Questions to Consider

- If Godot export is Lootbox’s payoff, why does it receive less explanation than clearing a regenerable cache?
- What would change if every bulk edit answered, at a glance, “which assets, from which packs, are about to change?”
- Could “local and untouched” become a visible promise at import, recovery, and export boundaries?
